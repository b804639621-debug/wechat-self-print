# 微信扫码自助打印系统 — 设计文档（Spec）

- 日期：2026-08-20
- 状态：设计已确认，待实施计划
- 前置文档：`实现方案调研报告.md`（项目根目录，含协议调研与开源底座选型依据）

---

## 1. 背景与目标

店内自助打印场景：顾客用微信扫描小屏幕上的二维码，登录微信文件传输助手网页版，通过自己微信的"文件传输助手"发送文件；系统后台自动接收并下载文件；管理员（店员）电脑上弹出打印界面，选择打印机、彩色/灰度、份数等设置并预览确认后执行打印；服务结束后登出会话并删除顾客文件。

## 2. 需求基线（已与需求方确认）

| # | 决策项 | 结论 |
|---|---|---|
| 1 | 收费 | 系统不管钱，店员线下人工收费；无计价/支付模块 |
| 2 | "修改"功能 | 界面提供"打开文件编辑"按钮，调系统默认程序（Word/WPS）打开，管理员改完另存后再选新文件打印 |
| 3 | 文件格式 | 尽量全收：PDF/图片/Office 自动入打印管线；zip/rar/7z 等其他格式照收但标红，管理员人工处理；>25MB 为微信协议硬限制（发送端被微信拦截），小屏引导文案预先告知 |
| 4 | 打印机 | 多台、含彩色机；界面必须支持选打印机 + 彩色/灰度切换；需对现场实机做彩色设置兼容性验证 |
| 5 | 并发 | 单队列：同一时刻服务一位顾客，服务期间小屏显示"服务中请稍候" |
| 6 | 隐私红线 | 服务结束即：登出微信会话 + 删除顾客文件 + 归档任务记录 |
| 7 | 小屏硬件 | 微雪 ESP32-C6-Touch-AMOLED-2.16 一体板（480×480 AMOLED，WiFi 6，约 200 元）；屏幕只显示二维码+一行短提示，引导教程用纸质立牌；烧屏防护 4 条见 §6.1；唤醒方式：店员点托盘图标点亮+强制刷新二维码（平时息屏） |

## 3. 服务流程

### 3.1 主流程

```
阶段0 待机 ──► 阶段1 建联 ──► 阶段2 传文件 ──► 阶段3 设置 ──► 阶段4 打印 ──► 阶段5 收尾
```

- **阶段0 待机**：主控常驻；小屏默认**息屏**，顾客到店时店员**单击托盘图标点亮小屏并强制刷新出全新二维码**（引导教程见柜台纸质立牌）；管理界面待机。
- **阶段1 建联**：顾客扫码 → 手机微信弹出"登录文件传输助手网页版"确认 → 顾客点【登录】。系统轮询到状态：小屏依次显示"已扫码请确认"→"已连接请发文件"；**登录成功后小屏立即撤下二维码**（防第二位顾客误扫）；管理界面显示"顾客已接入"。
- **阶段2 传文件**：顾客在自己微信"文件传输助手"发文件（可多个）；系统逐个下载到 `inbox/`；管理界面弹窗+提示音；**顾客跟发的文字消息作为备注实时显示在管理界面顶部横幅**。
- **阶段3 设置**：管理员点文件预览（PDF 逐页/图片直显/Office 转 PDF 后预览）；设置打印机、彩色/灰度、份数、页码范围、单双面、纸张；与顾客线下口头确认并收费。
- **阶段4 打印**：打印引擎执行；状态 打印中→已完成/失败（显示原因，可一键重打）。
- **阶段5 收尾**：管理员点"完成服务并登出"（默认手动；可配置为全部打印完成后自动执行）：登出微信 → 删除 inbox 文件 → 任务归档 → 小屏重新出码 → 回阶段0。

### 3.2 异常流程

| 异常 | 处理策略 |
|---|---|
| 二维码 240 秒过期 | 息屏期间不刷新（无消耗）；点亮屏幕时强制换新码，亮屏期间临近过期自动续期，顾客无感 |
| 扫码后 2 分钟未确认 | 自动作废该码出新码 |
| 连接后 5 分钟无文件 | 管理界面黄条提醒，店员决定等待或一键结束服务 |
| 微信会话掉线 | 先用持久化凭证静默恢复（最多 3 次）；失败则登出出新码，小屏提示重新扫码 |
| 文件 >25MB / 格式不支持 | 管理界面标红+原因，店员口头告知顾客 |
| 打印失败（缺纸/卡纸/离线） | 任务标失败+原因，会话不自动结束，处理后一键重打 |
| 主控程序重启 | 恢复 SQLite 未完成任务；凭证有效则免扫码恢复会话 |
| 登出/清理失败 | 记录日志并重试，界面强制告警（隐私红线） |

## 4. 系统架构（已确认：方案 A 全 Python 单体）

```
                 ┌──────────── 管理员电脑（Windows）────────────┐
  ESP32-C6 小屏  │                                              │
(AMOLED一体板)◄──┤  主控服务（单进程 + 系统托盘图标）            │
 轮询/api/screen │   微信协议客户端 ──► inbox/ + SQLite          │
  柜台立牌(纸质) │   FastAPI：/admin（管理）/api /WS             │──► 打印机A/B/C
  管理员浏览器 ◄──┤   打印引擎：LibreOffice转PDF → SumatraPDF     │
  /admin 页      └─────────────────────────────────────────────┘
```

- 底座：开源项目 `CJackHwang/wx-filehelper-api`（Python/FastAPI，协议实现经调研逐行验证，2026 年持续维护）
- 新增功能全部以**插件 + 独立模块**形式挂载，不改底座内核，便于跟随上游更新
- 降级路线：协议失效时切换浏览器自动化（Playwright）或微信小程序 `wx.chooseMessageFile` 合规方案
- 小屏显示服务抽象：主控暴露统一显示接口，硬件端只负责呈现，换硬件不改主控

## 5. 模块拆分

| 模块 | 职责 | 来源 |
|---|---|---|
| `direct_bot.py` 协议客户端 | 二维码、登录轮询、收消息、下载、心跳、登出 | 复用底座 |
| 消息下载落盘 | 自动下载到 `inbox/{日期}/` | 复用底座（AUTO_DOWNLOAD） |
| `plugins/print_shop/` 打印店插件 | 监听文件下载完成→创建打印任务；挂载 /screen、/admin 页面与任务 API；WebSocket 推送 | 新增 |
| `session_manager.py` 会话编排 | 状态机；二维码 240s 生命周期；亮屏/息屏状态机；收尾（登出+删文件） | 新增 |
| `print_engine.py` 打印引擎 | 枚举打印机；格式归一化；预览渲染（PyMuPDF）；组 SumatraPDF 命令执行；退出码解析 | 新增 |
| 系统托盘（pystray 线程） | 左键单击=点亮小屏+强制刷新二维码；右键菜单=打开管理界面/状态/声音/退出；图标随状态变色（灰=待机息屏、绿=服务中、红=异常） | 新增 |
| SQLite `print_jobs` 表 | 任务状态与打印参数持久化 | 新增 |

### 5.1 数据流

- **收文件**：微信消息 → 协议客户端下载 → `inbox/` → 写 `print_jobs(pending)` → WS 推送（/admin 弹窗+提示音，/screen 显示"已收到 N 个文件"）
- **预览**：/admin 点文件 → 引擎归一化为 PDF（带缓存）→ PyMuPDF 渲 PNG → 前端逐页显示
- **打印**：/admin 点打印 → 引擎组命令执行 → 退出码回写状态 → WS 推送双端
- **收尾**：点"完成服务" → 登出微信 → 删 inbox 文件 → `print_jobs` 归档 history 表 → 申请新二维码 → /screen 回待机

### 5.2 格式归一化管线

| 格式 | 处理 | 预览 | 打印 |
|---|---|---|---|
| pdf | 直通 | ✅ 逐页 | ✅ 直打 |
| jpg/png/bmp/gif/tif/webp | Pillow 转单页 PDF | ✅ | ✅ |
| doc/docx/xls/xlsx/ppt/pptx | LibreOffice headless 转 PDF | ✅ 转后逐页 | ✅ 转后打 |
| zip/rar/7z 及其他 | 照收，列表标红"需人工处理" | ❌ 提供"打开所在目录" | 人工 |

## 6. 界面设计

### 6.1 小屏显示端（已定案：ESP32-C6 AMOLED 一体板 + 纸质立牌）

**硬件**：微雪 ESP32-C6-Touch-AMOLED-2.16 一体开发板（ESP32-C6 / WiFi 6，2.16 英寸 480×480 AMOLED 电容触摸屏，CO5300 显示驱动（QSPI）+ CST9220 电容触摸（I2C），USB-C 供电，约 200 元）。

**固件**（Arduino，约 250 行）：
- 启动：WiFiManager 配网（首次开机自启热点，手机连上填店内 WiFi 密码存 Flash）→ 连接主控局域网地址
- 主循环：每 1.5 秒 `GET /api/screen/state` → `{ state, display, qr_content, file_count, message }`
- 传输通道（2026-08-25 Task 10B 起）：编译期二选一——TRANSPORT_BLE（现役：BLE 广播 + GATT 收发，空闲面板 ALDO3 彻底断电、WiFi 关闭，唤醒=主控连接后写 screen_state）/ TRANSPORT_WIFI（回滚：上述 WiFiManager 配网 + 1.5s 轮询路径）；GATT 契约与延迟实测见实施计划 Task 10B
- 主控侧 BLE 推送模型（2026-08-26 同步，Task 10B S2/S4 落地）：**懒建连**——首次 display=on 推送才建连，display=off 未连接时纯丢弃；服务结束后 **120s 快速重醒窗口（主控计时）**，窗口内保持连接免建连、到期主动断开回广播；空闲期 **15min 周期连接**读 link_status + 电池首包，兼作小屏在线心跳（管理页电池置灰阈值 `stale_after` = 心跳间隔 + 300s，后端下发）；诊断入口 **`--ble-selftest`**（建连就绪 → 等电池首包 → 读 link_status → 亮占位屏 → 息屏，PASS/FAIL 退出码）
- 二维码显示：主控用 pyzbar 解码二维码 PNG 得到**内容字符串**下发，固件用 `ricmoo/QRCode` 库**本地重新生成位图**（传输 <100 字节、显示锐利，不传 PNG 不解码）；显示驱动以微雪官方 Gitee 例程仓（waveshare/ESP32-C6-Touch-AMOLED-2.16）的 CO5300 驱动为准
- 息屏：全黑填充（AMOLED 黑像素不发光，物理等效息屏；若驱动支持 displayOff 命令则更彻底）
- ~~触摸唤醒（可选增强）~~：2026-08-25 决策放弃——唤醒仅保留管理员点击系统托盘图标；Task 10B BLE 通道不再初始化 CST9220，现役 WiFi 固件同步去除（commit 940f52b）

**烧屏防护（4 条，需求方定）**：
1. 每次刷新二维码时绘制起点随机偏移 ±10px
2. 亮度限制 80%（CO5300 亮度命令，初始化设置一次）
3. IDLE 待机/服务结束状态 3 分钟无变化自动息屏；**服务流程中（已扫码/已连接/收文件/打印中）保持常亮**
4. 管理员点击托盘图标 = 点亮 + **强制换全新二维码**（保证 240 秒满血有效期）

**状态显示内容**（屏幕仅二维码 + 一行短提示，详细引导由立牌承载）：

| 系统状态 | 屏幕显示 |
|---|---|
| IDLE（display=on） | 二维码居中（随机偏移）+ 一行"微信扫码·传文件打印" |
| IDLE（display=off） | 息屏全黑 |
| SCANNED | 二维码变暗 + "请在手机上确认登录" |
| CONNECTED | 撤码，"已连接，请发送文件" |
| RECEIVING | "已收到 N 个文件，请稍候" |
| PRINTING | "打印中，请稍候" |
| 主控不可达 | WiFi 轮询通道：亮"系统维护中"并继续重试。BLE 通道（Task 10B 起现役）：仅服务保持期（BLE 连接存续中）断连才常亮"系统维护中"（黑底白字、30s 微移防烧屏）；空闲期本无连接，保持休眠黑屏、不主动亮屏报错 |

**纸质立牌**（A5 竖版，实施时生成可打印 PDF）：三步图文引导（①微信扫码 ②手机点【登录】③文件传输助手发文件）+ 单文件 25MB 限制 + 支持格式 + 隐私公示"打印完成后立即退出登录并删除文件"。

**开发期辅助**：主控仍提供浏览器版 `/screen` 页（同一份状态数据），用于无硬件时的全链路联调与固件显示效果参照。

### 6.2 /admin 管理界面（给店员看，浏览器单页三区布局）

```
┌──────────────────────────────────────────────────────────────────┐
│ 状态条: 🟢服务中(已收3个文件) │顾客备注横幅│🔔声音开关│[完成服务并登出] │
├──────────────────────┬───────────────────────────────────────────┤
│ 文件列表(新文件置顶)   │  预览区(逐页PNG,翻页)      │ 打印设置面板      │
│ 复选框+格式图标+文件名  │                            │ 打印机下拉/彩色灰度 │
│ 大小·页数·时间+状态徽标 │                            │ 份数/页码/双面/纸张 │
│ [全选][批量打印]       │                            │ [开始打印][打开文件]│
│                      │                            │ [打开目录][作废][重打]│
└──────────────────────┴───────────────────────────────────────────┘
```

交互要点：
- 新文件：提示音（可关）+ Toast + 列表置顶插入
- 顾客文字消息：顶部备注横幅显示，店员手动清除
- 多文件：复选批量打印（共用当前设置）
- 默认值记忆：自动带出上次打印机/色彩/纸张（存后端配置文件 config.json，多浏览器访问表现一致）
- 标红文件：只给"打开所在目录"
- 打开文件编辑：`os.startfile()` 系统默认程序打开，另存后重新选文件打印
- 失败重打：卡片显示原因，一键重打

## 7. 打印引擎设计

- **枚举打印机**：`win32print.EnumPrinters` 或 `SumatraPDF -list-printers`
- **执行命令**：
  ```
  SumatraPDF.exe -print-to "<打印机名>" -print-settings "<color|monochrome>,<份数>x,<页码范围>,<simplex|duplexlong|duplexshort>,paper=<纸张>,fit" -silent "<PDF路径>"
  ```
- **退出码**：0 成功 / 2 文件打不开 / 4 打印机不存在 / 5 驱动失败 → 映射为界面可读原因
- **彩色/灰度兜底**：若个别驱动不认 SumatraPDF 的 monochrome 参数，用 pywin32 `DocumentProperties` 改 `DEVMODE.dmColor`（DMCOLOR_MONOCHROME=1 / DMCOLOR_COLOR=2）
- **预览渲染**：PyMuPDF 按页渲 PNG（150 DPI），转换结果缓存避免重复转

## 8. 会话状态机

```
IDLE(出码待机) ─扫码→ SCANNED(待确认) ─确认→ CONNECTED(等文件)
  ↑                    │2分钟超时                │收到文件
  │                    v                         v
  │                  IDLE                     RECEIVING(下载中)
  │                                                │下载完成
  │                                                v
  │                                            READY(待打印) ─点打印→ PRINTING
  │                                                ↑                     │
  │                                                └──失败重打──────────┤
  │                                                                      v
  │                                                全部完成 ←── 完成/失败
  │                                                  │管理员收尾
  └────────── 登出+删文件+归档+出新码 ──────────────┘
```

## 9. 数据模型（SQLite）

`print_jobs`：`id, msg_id, file_name, file_path, format_category(pdf/image/office/other), size_bytes, page_count, status(pending/printing/done/failed/discarded), print_options_json(printer/color/copies/pages/duplex/paper), error_reason, created_at, printed_at`

`print_history`：收尾时从 `print_jobs` 归档（保留打印日志，删除文件实体）。

顾客文字备注消息：不进库，仅 WS 实时转发 /admin 顶部横幅。

## 10. 测试策略

- **M1 链路验证（最先做）**：真实微信账号跑通 扫码→发 PDF→下载→SumatraPDF 打印
- **打印引擎**："Microsoft Print to PDF"虚拟打印机做无纸自动化测试；彩色/灰度、双面在现场多台实机逐一验证
- **格式管线**：样本文件集批测（各格式+超大+损坏文件）
- **界面**：手工走查全流程 + 异常注入（断网、关打印机、会话掉线）

## 11. 风险与限制

1. 协议为逆向实现，微信可能改协议/风控 → 接入层与业务解耦，关注上游更新，降级路线见 §4
2. 单会话单顾客串行服务（协议硬约束）
3. 顾客需两次操作（扫码+手机确认登录），小屏引导必须清晰
4. 单文件约 25MB 上限
5. 会话空闲超时掉线 → 心跳检测+自动重新出码
6. 隐私红线：打印完成必须登出+删文件，界面公示

## 12. 里程碑

- **M1 打通链路**：wx-filehelper-api 跑通扫码→发文件→下载→命令行打印（风险最高，最先验证）
- **M2 小屏与管理页**：`/api/screen/state` 显示接口 + ESP32 固件（配网/轮询/二维码生成/烧屏防护）+ 托盘程序 + /admin 界面（列表/预览/打印机/彩色灰度）
- **M3 完善**：Office 转 PDF、状态机、自动登出与刷新、批量打印、打印日志、隐私清理
- **M4 加固**：断线重连、凭证过期自动出码、PyInstaller 打包 exe 开机自启、实机兼容性测试
